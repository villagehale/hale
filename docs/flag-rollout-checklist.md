# Staged enablement checklist

VIL-405, corrected in VIL-557. Merging this page leaves every flag where it is.

This page says what each flag does, how its value is parsed, what the code does when it is unset, which flags depend on which, the order to light them in, the probe, and the rollback and kill. It never says what a flag holds in any environment or whether it is set. The live production values are recorded privately in Linear (the 2026-11-03 flag table on the document ["Product direction 2026-09-21"](https://linear.app/villagehale/document/product-direction-2026-09-21-the-activity-finder-loop-read-before-bca7b5c32d03)) and must never be copied into this repo, its pull requests or its commit messages.

Parsers cited at origin/main `1017409437f8`. `apps/worker` reads two product flags, `AUTONOMOUS_EXECUTE_ENABLED` and `ASK_POLICY_TIERS_ENABLED`, in the orchestrator that `apps/web` runs from `/api/cron/drain`. Eval scripts read `EVAL_GATEWAY_MODEL` only when someone runs an eval.

Kill switch, every time: set the value on the Vercel production project for `apps/web`, then redeploy that project.

Launch flags are also catalogued in `@hale/flags` and evaluated through `isEnabled` / `flagValue`. `POSTHOG_FLAGS_ENABLED` is off unless exactly `true`; while off, every reader is today's env parser. Once on, an explicit env `false`/`off` (or `VOICE_DISABLED=true`) kills the flag regardless of PostHog; otherwise the family-hashed local PostHog flag is used, and a miss falls back to the env value. `BROWSER_USE_SIGNUP_PAYMENT_ENABLED`, `LINQ_APP_CLIP_PAY_ENABLED`, `ANTHROPIC_CREDIT_ALERT_ENABLED`, `HOLIDAY_PROMO_ENABLED`, `CONVERSIONS_API_ENABLED`, `META_CAPI_ENABLED`, `CHECKOUT_SERVER_CURRENCY_ENABLED`, `STRIPE_BILLING_REVOKE_ENABLED`, `STRIPE_REFUND_ENDS_SUBSCRIPTION_ENABLED`, `STRIPE_CLEAR_DELETED_SUBSCRIPTION_ENABLED`, `CHECKOUT_SUCCESS_STATES_ENABLED`, `MAX_ENTITLEMENTS_ENABLED`, `INGEST_BODY_MAX_ENABLED`, `FAMILY_SCOPED_SEND_KEYS_ENABLED`, `PARENT_SEND_RECEIPT_ENABLED`, `PARTY_GUEST_MODEL_COPY_ENABLED`, `PLAN_OPS_STOP_ENABLED`, `ASK_POLICY_TIERS_ENABLED`, `THIRD_PARTY_INVITE_ROUTE_ENABLED`, and `NUDGE_MODEL_ONLY_ENABLED` stay env-only. Sync PostHog with `pnpm posthog:sync-flags -- --dry`.

`true` means the value is exactly `true`, with no extra characters. `trimmed true` (written `true` (trimmed)) means trim, then exactly `true`. `on` means trim, then exactly `on`. `on` (no trim) means exactly `on`, with no trim (`SOCIAL_WATCHLIST`). `true`, `ON`, and `1` do not turn an `on` flag on.

The Unset column says what the parser does when the variable is unset:

- `ON` / `OFF`.
- `current`: a model-mode flag; the default model runs.
- `voice runs`: `VOICE_DISABLED` is inverted; unset, voice compose runs.
- `off` mode: `PROACTIVE_CADENCE` resolves to its `off` mode. The hourly review reads no family and sends nothing. Sweeps that still send on their own clock keep doing so until `PROACTIVE_SENDS_PAUSED` is exactly `true`. It is a mode, not an on/off flag. `REGISTRATION_DATE_CHECK` works the same way: unset is `off`, and no registration page is read.
- `200 USD (code default)`: `ANTHROPIC_SPEND_ALERT_USD` is config, not a flag.
- `40 USD (code default)`: `ANTHROPIC_CREDIT_ALERT_USD` is config, not a flag. `ANTHROPIC_CREDIT_START_USD` / `ANTHROPIC_CREDIT_START_AT` have no default; unset is `start_not_configured`. `ANTHROPIC_CREDIT_EXPIRES_AT` unset skips expiry warnings. `ANTHROPIC_CREDIT_EXPIRY_WARN_DAYS` unset is 7 then 3.
- `no runtime chosen`: `SIGNUP_BROWSER_RUNTIME` picks no signup browser runtime.
- `OFF (preview-only)`: off, and it can only turn on in a Vercel preview.
- `no reader on main`: no source on main reads the variable; a stored value does nothing.

The four lane switches (VIL-226) hold work while they are off. They do not delete it. Like every other `true` flag above, the value must be exactly `true`: a piped `echo` stores `true` followed by a newline, which keeps the lane off. Set it with `printf '%s' true`, then redeploy. `TRAVEL_BRIEF_ENABLED` is read through the same helper under its own name.

- With `CALENDAR_ALERT_ENABLED` unset, both the 1:1 calendar text and the Linq household calendar notice are off. The sweep still remembers each change. A calendar text Hale already owes stays owed and is offered again when the lane is back on. One older than the usual pending limit is aged out by the lane-off sweep itself (`pending_expired`), so its held title and location are cleared on time. Kid events not yet told to the group stay unannounced until then. Passport stamps inferred from calendar changes follow this switch too: with the lane off no calendar stamp is written, even with `INTEREST_PASSPORT_ENABLED=true`, and the sweep returns `passport: 'lane_off'`. This includes a seeding run (a connection's first sync, or a full resync Google forces after a stale sync token).
- With `PARENT_CALENDAR_MIRROR_ENABLED` unset, mirrored `family_events` rows stay in the database and no new reminders are created for them (counted as `notScheduledLaneOff` in the reminders cron response). Reminders already scheduled stay `scheduled` and are counted as `heldLaneOff`. The connector sync logs the held window with `heldReason: 'lane_off'`.
- A reminder whose time passed (held by a lane, or late after a cron gap) is never turned into `missed` by a time window. When it is next classified it is sent if its event has not started (counted in `firedLate` beside `fired`), an evening-before reminder on the event's own day included, and dropped as `started` once the event has begun. A reminder opens with its event's own local date, never a word like "tomorrow", and the voice phrases the day from the event's local start and the send moment. Each drop is logged as `reminder: dropped, not sent` with its reason and writes a `reminder_suppressed` audit row. The per-family send decider (#859) does not classify reminders, so this rule decides.
- With `REGISTRATION_LADDER_ENABLED` unset, the registration-sequence cron runs no ladder and answers `{ lane: 'registration_ladder', outcome: 'lane_off', groupSync: 'lane_off' }`. The sequence rows are left as they are, so a leg whose window is still open goes out once the lane is back on. The group-decision flush in the same route is held too: those syncs send group bubbles.
- `REGISTRATION_PLAN_AT_OPEN_ENABLED` (env-only, exact `true`; nothing in PostHog may turn it on) stops the plan sweep from claiming or starting a registration before `plan_opens_at`. While it is off, the sweep still joins up to three minutes early. An abandoned claim with no provider run is put back to `planned` and the parent is not texted. A live lease is left alone. A run that already has a provider session is left in place.
- `PLAN_CITY_LOGIN_OWNER_ENABLED` (env-only, exact `true`; nothing in PostHog may turn it on) lets a plan run use a saved city login or captured session only when that parent saved it. The day-before prep asks that parent for their own login when the only one on file is the co-parent's. A co-parent's plan does not receive the other parent's username, password, TOTP, or cookies. There is no share grant. Browser Use `secretBindings` are unchanged. While the flag is off, a plan still loads the family's one login for that host.
- `SIGNUP_HELP_SLOT_RELEASE_ENABLED` (env-only, exact `true`; nothing in PostHog may turn it on) gives a Plus/Free season sign-up slot back when Browser Use throws before any provider session exists, or the page comes back `rush` because registration is not open yet. A provider-side failure, and a throw that does not say whether a session started, still count. Max stays unlimited. While the flag is off, those endings keep the slot.
- `REGISTRATION_PLAN_RUN_ENABLED` carries out a parent's day-before registration plan at the open and pays with the card saved on the parent's city account. The payment also needs `BROWSER_USE_SIGNUP_PAYMENT_ENABLED` exactly `true`; without it the plan stops at checkout with `payment_off` and the parent pays on the live browser. Before paying, a read-only checkout review in the same browser chooses the saved card and stops on the last page before "place order"; code checks the total read there against the maximum and the spending cap and pays only that exact total. A review that says it placed the order ends `review_placed_order`, keeps the browser open, writes a `plan_payment` row with no amount, and pages Slack #ops (`registration_review_placed_order`, ref = the offer id). **Do not arm it while Browser Use can solve a CAPTCHA on a plan run.** Hale never solves or gets around a CAPTCHA (2026-11-04 decision). Plan runs are Browser Use V4 agent runs. Browser Use solves CAPTCHAs on agent runs by default, and V4 run `browserSettings` has no `solveCaptchas` field (https://docs.browser-use.com/cloud/browser/captcha-handling). A run cannot attach to a browser Hale created with `solveCaptchas: false`, because `POST /runs` takes no browser id. Arm it only after one of these: Browser Use confirms in writing that solving is off for Hale's project, or V4 adds a run-level `solveCaptchas` and the plan engine sends `false`. Browser Use's EU deployment has solving off, but moving there needs a data-residency decision under hard rule #1, so it is not a quiet switch. ## First five families

The first five real families are watched every day until each has been on the thread for seven days. Noah posts one summary to Slack `#ops` each day. Sloane adds a line when a parent-visible sentence was wrong. Eugene adds a line when a `HALE_*_MODEL_MODE` flag is `candidate` or when turn latency jumped.

Each day's note names the five family ids and these counts:

1. `channel_messages` for those families: `failed` versus `sent` and `delivered`, split by category (`duty_ask`, onboarding, `followup`).
2. `audit_log` rows with `action_taken` = `sms_turn_failed`.
3. No-reply gaps: an outbound ask with no inbound from that parent for 24 hours.
4. Latency from the inbound `channel_messages` row to `sms_turn_answered`.
5. Opt-outs: STOP, new `email_opt_outs` rows, `same_activity_opt_in_revoked`.

A failed send, a `sms_turn_failed` row, a STOP, or a no-reply gap tied to a flag that is on is a kill the same day. The owner sets that flag's kill value and redeploys `apps/web` before the next send window. The summary says which flag was killed.

`SAME_ACTIVITY_MEET_ENABLED` does not send: its delivery returns `skipped: 'not_configured'` (`apps/web/lib/channel/same-activity/copy.ts:122-124`). For it, the kill signal is a `channel_messages` row from that path, not a no-reply gap.
